# TECHNICAL DEBT: 

Technical Debt is the concept where working "hastily" or "quick and dirty" right now instead of using a better approach means 
that you or someone else will have to rewrite that specific part thanks to you.

 It is possible to reduce technical debt by creating incremental product.
 It is also possible to reduce the technical debt by refactoring. 

> Best Approach: Reduce the technical risk as you go, its better to pay off the loan, gradually, then at once in the end (in the 
> end the interest payed is higher).

# QUALITY MANAGEMENT PLANNING: 
 It is not enough to just say we need "quality". What the team/developers mean by quality should be predefined. then we create a 
 set of activites that will help ensure quality for each and every work product. after that we perform quality control and 
 assurance activities on every software project, use metrics to develop strategies for quality.

> EVERYONE CONTRIBUTES TO THIS 
 
 This is important if every contributor stresses on quality, less rework there is to do after the product has been produced. 

### WORK PRODUCT: 
 A SQA Plan is created to define the software teams SQA strat. Also during the testing phase tests plans and procedures are 
 designed. There may be other products as well.

### SQ METRICS: 
 Code Quality: 
    -> Code Churn: 
        Measures the number of lines added, modified or removed from the code For example if in a project 500 lines were added, 
        200 were modified and 100 were removed, the total churn would be: 500 + 200 + |-100| = 800

  Reliability: 
	Mean Time Between Failure(MTBF): This metric indicates how long a software runs on average before encountering a 
    failure. Higher MTBF signifies more reliability.
