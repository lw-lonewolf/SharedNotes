# TOOLS 
Softwares or programs that are not related to the project but assist in creating it are tools. i.e. they 
are not PART of it, just the stuff that helps make it. examples may be Office (when writing an SRS for 
example), Figma for the Design Phase. VS CODE for the coding phase etc.

> CASE stands for Computer Aided Software Engineering (how else are we fucking supposed to do it, i wonder?)

Each tool has a specific and single activity such as editing, compilation, debugging and so on. Some 
purposes of theirs include:

1) Storing Programs, Sharing them with others
2) Graphical Design, Animations
3) Team Activities Management
4) Discussion Forums
5) Editors
    -> Textual (Vim, i wrote these notes in that :p) 
    -> Graphical (Vs Code obv) 
6) Linkers: Bind names and basically link different files together. 
7) Interpreters: 
    Execute actions specified in a formal way (the compiler of python is an interpreter i believe) 
8) Code Generators (compilers): 
    We all know what they do. (compile obv.) e.g MinGW, Clang
9) Debuggers: 
    Debug code or run it line by line. e.g. GDB & VS BUILT IN DEBUGGER
10) Testing tools: 
    may be used to document them, design or evaluate tests
11) Static Analyzers: 
    sort of like compilers but do not compile the code directly. instead they "scan" the code to try and 
    find problems (such as `uninit. variables` before compilation can take place.

12) GUI Tools: 
    The kind that help design shit. 

13) Configuration Management Tools: 
    Repositories and Version Management: Github for example 

14) Tacking Tools: Track progress and defects. (like maybe that shit we used for creating the kanban 
    could be used for progress tracking)

15) Reverse and Reengineering Tools: 

    Understanding Existing Legacy Systems and then transforming them to new tech. 

Comparing Tools can be done on the following factors: 

> Interaction Mode: The way users interact with the tool, such as command-line, GUI, or API-based. 
> Interface Format: The type of interface provided, like graphical, textual, or hybrid. Level of 
> Formality: The degree of rigor and structure the tool enforces, from informal to highly formal. 
> Dependency on Lifecycle Phase: The tool's applicability and relevance to specific phases of the 
> software development lifecycle.
