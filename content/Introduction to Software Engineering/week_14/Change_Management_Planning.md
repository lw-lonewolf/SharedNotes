# CHANGE MANAGEMENT PLANNING 

Change is inevitable especially in software engineering, there are various points everyday when something is getting changed :P 
Software Change Management is a branch that manages the changes. Everyone is involved in it. but sometimes there may be special 
people whose sole purpose is SCM.

 *IMPORTANCE*: If control is not managed properly it ends up controlling you. Unless you manage 
change properly even a good project can turn into chaos within seconds.

 First all work products must be uniquely identified. Once this is done, different techniques can be used for version control and change controlling.


### WORK PRODUCT : SCM PLAN (DEFINES PROJ STRAT FOR CHANGE MANAGEMENT) 
 Change also results in updated software products that must be retested and documented, without breaking the project schedule or 
 the production version of the software products.

You've done right when each and every product can be tracked, controlled, accounted for analyzed and everyone is up to date with 
all the changes that took place.

## WHY CHANGE? 
Software is malleable and has a flexible form. It can change at any point in production thanks to the fact that the user 
requirements can change or the developer may want to use a better approach or the management has a better approach to do 
something that will be the optimum way to move forward while also ensuring monetary benifits

## BASELINE: 

A baseline is a software config management concept that helps you manage change without seriously impeding justifiable change. "A 
spec of product that has been formally reviewed and agreed upon and thereafter serves as the basis for further development, and 
then can be changed only through formal change control procedures."

Before a baseline is implemented, changes may be quick or informal but after a baseline is established changes can only be made 
only when a specific formal procedure is applied in order to evaluate and verify each change before passing it on.
