# The Water Fall Model Components: 
1) Communication
-> project init  -> requirements gathering
2) Planning 
-> estimating, tracking, scheduling
3) Modelling
-> analysis & design
4) Construction
-> coding testing
5) Deployment
-> delivery, support, feedback

## Benifits 
-> simple, easy to use, easier to manage, works well when requirements are very well understood

## Drawbacks
-> Doesn't work well for complex/OOProjects
-> high risk of failure, problems wont be recognized before the last stage
## When to Use: 
-> Requirements are well understood and prob wont be changed. 
-> When a linear, sequential approach to dev is required.
