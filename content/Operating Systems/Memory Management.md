
#### Internal Fragmentation
Space inside a fixed-size memory segment that is wasted.
#### External Fragmentation
Holes outside any region that is when free memory space exists to load a process in the memory but the space is not contiguous. *Compaction* is used to deal with that. It works by shuffling memory contents to place all free memory into one large block. The cost is slower execution of processes as compaction takes place. 

#### Paging: 
All programs and data are composed of fixed length units that we normally call *pages* i.e. logical memory is divided into blocks of same size called pages. It is a block of words that occupy contiguous locations in main memory. The physical equivalent of pages are *frames* and have the same size as a page. 

>[!important] 
Every logical address generated by the CPU is divided into two parts. 
> * Page number (p) high-order bits 
> * page offset (d) low-order bits 


The page table contains the base address (or frame number) of each page in physical memory. The frame number is then combined with the page offset to obtain the physical memory address of the memory location that contains the object addressed by the corresponding logical address. 
The physical address of the location referenced by *(p,d)* is computed by appending d at the end of *f* as : 
	*f* + *d* 
	Where *f* is the base address and d is the *page offset* 

**LOGICAL ADDRESS:** *p* + *d* 
**PHYSICAL ADDRESS:** *f* + *d* 

#### Key Formulae for Paging Numericals

##### Number of bits for Page Number (*p*) 
$\text{Bits for p} = |\log_{2}{\text{Number of Pages}}|$
e.g. For 16 pages numbers of bits needed would be *4 bits* 

##### Number of Bits for Frame Number (*f*)
Bits for $f$ = $\log_{2}{\text{Number of Frames}}$
For 32 frames this would be *5 bits* 
##### Number of Bits for Offset (*d*)
*d* is the number of bytes required to locate an exact byte within a page/frame

Bits for $d$ = |$\log_{2}{\text{Page Size in Bytes}}$|

##### Logical Address Size
Logical Address Size = Bits for *p* + Bits for *d*

##### Physical Address Size 
Physical Address Size = Bits for *f* + Bits for *d*

##### Page Table Size
Page Table Size = Number of Pages * PTES 
>[!important] PTES (Page Table Entry Size)
>Page Table Entry Size = *f*
>**IN PRACTICE WE ROUND PTES UPWARDS TO THE NEXT BYTE (e.g. if 5 bits = f then PTES = 1 byte)**

##### Maximum Number of Pages in a Address Space 
Number of Pages = $\frac{\text{Process Address Space}}{\text{Page Size}}$
Process Address Space = $2^{\text{Number of bits in Logical Address}}$

###### Maximum Number of Frames in Physical Memory 
Number of Frames = $\frac{\text{Physical Memory}}{\text{Page Size}}$


### Virtual Memory 
#### Demand Paging 
A demand paging system is similar to a paging system with swapping. Processes reside in secondary memory (maybe HDD). We swap the process into memory when it is to be used. Rather then swapping the entire process we use a *lazy swapper*. A lazy swapper never swaps an entire process into memory. A page is swapped into memory and only when it is required. A swapper manipulates entire processes while a pager is concerned with the individual pages of a process. **This scheme requires some sort of hardware support to distinguish between loaded and unloaded pages. The valid/invalid bit can be used for this.** This means when the bit is set to '*invalid*' it either means its is invalid OR valid but currently on disk.

### Page Faults 
What if a process tries to access a page not brought into memory. 
The paging hardware will notice through page table that invalid bit is set and will cause a trap to OS
Following steps will take place: 
* We check an internal table (usually kept with PCB for that process) to determine whether it is valid or invalid page address
* If invalid process terminates. If valid we load that page into memory.
-> If valid: 
* Find free frame
* Schedule disk operation to read page into that memory frame 
* Modify internal table kept with process to indicate page is in memory 
* Restart the instruction that caused the trap.
Now the process can access that page as if it was always in memory.

## Translation Look Aside Buffer 
CPU Registers are OK for small address spaces and large page sizes. It has the advantage of having a small effective memory access time i.e. about the same as the memory access time. 

*in the main memory, the* **Page Table Base Register** exists, used to point to the page table. Page table can not exist in the main memory due to the slow effective memory time. 

To overcome this we introduce the Translation Look-Aside Buffer. It is a hardware cache used by the MMU to speed up virtual to physical address translation in paging systems. Has about *64-1024* entries. Each entry as *(key,value)* The key value pair is *(p,f)* for paging. TLB is searched for p. If not found, page table in main memory is searched.

If *hit ratio* = **HR**  and *miss ratio* = **MR** Then effective access time is given as: 

**$T_{effective} = \text{HR}(\text{TTLB} + T_{mem}) + \text{MR}(\text{TTLB} + 2T_{mem})$**

## Page Table Structure 
The following schemes allow efficient implementations of page tables: 
* Hierarchical/Multilevel paging
* Hashed Paging Table 
* Inverted Page Table 

#### Hierarchical/Multilevel Paging 
A page table for modern systems can not fit in one page. One solution is to page the page table. resulting in a two level paging. A page table for keeping track of pages in a page table. and then a inner page table. 

Number of entries per page table = $\frac{\text{Page Size}}{\text{PTES}}$
Bits required to index these = $\log_{2}{\text{Number of Entries per Page Table}}$
