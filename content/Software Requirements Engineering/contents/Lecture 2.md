SRE Activities:
These are NOT stages, these are activities, they may not be performed in the same order or may even be performed in parallel.
* Inception
* Elicitation
* Elaboration
* Negotiation
* Specification
* Validation
* Management
*During requirements engineering all of these will be performed.*
##### Negotiation: 
Convincing the user to either change/reduce requirements. increase time/budget etc. 
##### Specification: 
Express the requirements etc.
##### Validation: 
Confirm the specifications from the client
##### Management: 
Not forgetting when, what and who gave each individual requirements (we're managing these) 

"No other part of the conceptual work is as difficult as establishing the detailed technical requirements. .... including all the interfaces to people, to machines, and to other software systems. No other part of the work so cripples the resulting system if not correct "
-- Fred Books.
### Users of a Requirements Document: 
System Customers
	* Check if their needs are met. 
Managers
	* Plan the development process 
System Engineers
	 * Understand what needs to be developed
System Test Engineers
	*  Develop test cases
System Maintenance Engineers
	 * Understand the system and its parts
### Role-Action in SRE Process (Who does what?)

| Action                            | Role                                                              |
| --------------------------------- | ----------------------------------------------------------------- |
| Understand the Problem            | Requirements Engineer, Domain Expert, End User                    |
| Establish outline of requirements | Requirements Engineer, End-User                                   |
| Select Prototyping system         | Software Engineer, Project Manager                                |
| Develop Prototype                 | Requirements Engineer, Software Engineer                          |
| Evaluate Prototype                | End User, Domain Expert, Requirements Engineer, Software Engineer |
