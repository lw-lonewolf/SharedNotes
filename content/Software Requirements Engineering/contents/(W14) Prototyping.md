Two types of prototyping -> 1) Throwaway 2) Evolutionary 
*Throwaway:* Supposed to be thrown away after showing to the customer (duh) 
*Evolutionary:* You build on top of this prototype.


| ---                    | ***Throwaway***                                                                                                   | ***Evolutionary***                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| ***Mock-Up***          | -> clarify + refine user functional requirements<br>-> identify missing functionality<br>-> explore UI approaches | -> Implement core functionalities<br>-> implement and refine websites.<br>-> additional functionality based on user reqs. |
| ***Proof of Concept*** | -> demo of technical feasibility<br>-> eval performance                                                           | -> implement and grow multi-tier functionalities <br>-> test + tune performance                                           |
##### Evaluating a Prototype: 
This basically means testing everything works as its supposed to. How to do this: 
-> Make users test product, (remember there are two types of users, idiots, and experienced users)
-> do NOT tell them HOW to do something, let them figure it out, and to evaluate loudly while doing so "oh where's that? etc." so you know what you can improve.
-> Make scripts for how to perform a certain action.
-> document all results you get from this, what you learned from this. 
-> resolve conflicts (if they exist) between requirements and the prototype
##### Questions that can be asked: 
-> Does it do what you expected it to do? 
-> What functionality does it miss. 
-> can you think of any error conditions this prototype doesn't address 
-> Are any unnecessary functions present
-> how logical or complete does the navigation seem. 

##### Success: 
Success of a prototype can be evaluated by: 
-> Development Schedule (was it made on time)
-> Customer Satisfaction (is the user happy)
-> high quality product

##### How to get to 'Success'
-> Include prototyping in project plan 
-> State the purpose of each prototype (what should be the outcome, what does it aim to show to the customer)
-> Invest MINIMUM on throwaway prototypes. (Avoid data validation, error-handling, extensive docs)
-> Plausible data on screen displays. 
-> Confirm that stakeholders have a shared understanding of the requirements (basically requirements are unclear if the evaluator does not agree with implementation)
