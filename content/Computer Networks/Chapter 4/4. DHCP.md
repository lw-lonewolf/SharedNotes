# How to get an IP address? 

There are three questions really: 
1. How does a host get an IP address within its network (host part of the address)
2. How does a network get IP address for itself (network (subnet) part of the ip address)
3. How does an ISP get a block of addresses 

## How does a host get an IP address?
* hard-coded by sysadmin in a config file ( e.g. `/etc/rc.config` in UNIX)
* DHCP: Dynamic Host Configuration Protocol: dynamically get address from server. also called "plug and play" due to its automatic nature.s

### DHCP
DHCP is an application layer protocol but uses UDP (transport layer) to help assign IP addresses (network layer).

>[!important] DHCP Ports 
>Port 67 and Port 68 are standard DHCP ports for DHCP Server and DHCP Client respectively.s

DHCP has a 4-step process (famously known as **DORA**): 
* Discover
* Offer
* Request
* Acknowledge

#### Discover 
Device broadcasts "Any DHCP Server? I need an IP"
e.g. connect mobile to internet
`(Device sends DHCP Discover (Broadcast)`

#### Offer
DHCP Server replies "I can give you `192.168.1.25"`. Interested?"
`DHCP Offer -> IP: 192.168.1.25`

#### Request 
Device replies "Yes. I want that one"
`DHCP Request -> requesting 192.168.1.25`

#### Acknowledge
Server confirms: "Done. It's yours for now"
`DHCP ACK -> IP assigned`

After this process your device now has: 
```sh
IP address: 192.168.1.25
Subnet mask: 255.255.255.0
Gateway: 192.168.1.1
```

### Leases
The ip assigned by DHCP isn't permanently yours. It's rented for a certain amount of time. (e.g. 24 hours). After this time has passed the device either **renews it**, or **gets a new one**

### Why use DHCP?
Without DHCP we would have to manually assign IPs to hosts, and networks would break daily due to humans, therefore DHCP automates everything, reuses IPs and supports devices leaving/joining the network.
